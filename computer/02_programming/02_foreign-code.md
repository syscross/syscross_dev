# 남의 코드 위의 모래성

Castles on Foreign Code

---

현대의 프로그래머가 에디터를 열고 코드를 짤 때, 실제로 자기 손으로 작성하는 로직이 전체 실행 코드에서 차지하는 비중은 얼마나 될까. 소프트웨어 공급망 보안 기업들의 조사에 따르면, 오늘날 상용 애플리케이션의 **70%에서 90%**는 개발자가 직접 짠 코드가 아니라 외부에서 가져온 오픈소스 구성요소다.

웹 서비스 하나를 띄우기 위해 `npm install`이나 `pip install` 한 줄을 치는 순간, 수백 개의 직접 의존성과 그 뒤에 꼬리를 문 **수천 개의 전이적(Transitive) 의존성 패키지**가 내 서버 안으로 쏟아져 들어온다. 현대 프로그래밍의 본질은 백지 위에서 논리를 창조하는 일이 아니라, **얼굴도 모르는 타인 수천 명이 무료로 올려 둔 코드 조각들 위에 얇은 접착제를 바르는 작업**에 가깝다.

## 11줄짜리 도미노와 500밀리초의 우연

남의 코드 위에 세운 성이 얼마나 취약한지는 두 사건이 적나라하게 증명했다.

2016년 3월, 한 개인 개발자가 상표권 분쟁에 반발해 자바스크립트 패키지 저장소(npm)에서 자신이 올린 패키지들을 삭제했다. 그중에는 문자열 왼쪽에 공백을 채워 주는 고작 **11줄짜리 코드 `left-pad`**가 포함되어 있었다. 그런데 이 사소한 11줄이 바벨(Babel)과 리액트(React) 같은 핵심 도구의 전이적 의존성에 걸려 있던 탓에, 단 몇 분 만에 페이스북·넷플릭스·에어비앤비 등 전 세계 기술 기업들의 빌드가 동시에 멈춰 섰다. 수조 원의 시가총액을 자랑하는 거대 인프라가, 무보수 개인이 올린 11줄짜리 모래알 하나가 빠지자 그대로 무너져 내린 것이다.

2024년 3월에 발각된 **XZ Utils 백도어 사건**은 이 취약성이 악의와 만났을 때 어떤 파국으로 이어지는지 보여 주었다. 리눅스 배포판 거의 전체에 기본 탑재되는 압축 라이브러리 `xz utils`는 사실상 **단 한 명의 자원봉사자**가 수년간 홀로 유지보수하고 있었다. '자 탄(Jia Tan)'이라는 가명을 쓴 공격자는 수년에 걸쳐 지친 유지보수자의 신뢰를 얻어 커밋 권한을 넘겨받은 뒤, OpenSSH 인증을 우회하는 정교한 백도어를 빌드 스크립트에 몰래 심어 넣었다. 이 치명적 침투가 전 세계 서버로 풀리기 직전에 겨우 잡힌 이유는 체계적 보안 감사 덕분이 아니었다. 마이크로소프트 엔지니어 안드레스 프로인트(Andres Freund)가 우연히 SSH 로그인에서 **500밀리초(0.5초)의 이상 지연**을 눈치채고 추적한 순전한 우연 덕분이었다.

## 20와트 두뇌와 책임 없는 생태계

왜 이런 기형적 구조가 표준이 되었는가. 답은 간단하다. 인간의 뇌는 사바나 환경에 맞춰진 **20와트짜리 제한된 연산 기관**이기 때문이다.

인간의 작업 기억은 동시에 서너 개 이상의 비동기 상태와 경합 조건이 얽히면 인과 추적을 놓친다. 바닥부터 모든 암호화, 네트워크, 파싱, UI를 혼자 다 짜고 검증할 수 있는 인간은 없다. 그래서 개발자들은 검증되지 않은 타인의 코드를 뭉텅이로 끌어다 쓰는 쪽을 택했다. 여기에 벤더와 플랫폼의 빠른 API 폐기(Deprecation), 강제 업데이트, 보안 패치 압박이 겹치면서 코드베이스는 가만히 서 있어도 썩어 간다(Software Rot).

문제는 **스킨 인 더 게임(Skin in the Game)의 부재**다. 무료 오픈소스 유지보수자의 60~70%가 무보수 노동과 만성 번아웃에 시달리지만, 그 코드를 공짜로 가져다 수조 원을 버는 기업들은 그 의존성 트리의 밑바닥을 감사하지 않는다. 코드의 90%를 남의 손에 맡기고도, 정작 책임은 아무도 지지 않는 모래성 위에서 현대 소프트웨어는 매일 아슬아슬하게 돌아가고 있다.
