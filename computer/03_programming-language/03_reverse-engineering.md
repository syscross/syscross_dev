# 리버스 엔지니어링

Reverse Engineering

---

반세기 동안 상용 소프트웨어 산업을 지탱한 성벽은 **컴파일의 일방향성**이었다. 기업은 소스코드를 금고에 가둬 두고, 인간이 읽을 수 없는 0과 1의 바이너리만 배포했다. 리버스 엔지니어링(Reverse Engineering)으로 이 벽을 뚫으려면 IDA Pro나 기드라(Ghidra) 같은 디컴파일러를 띄워 놓고, 심볼이 날아간 `sub_401000` 함수 수만 개를 인간 전문가가 수년간 손으로 해독해야 했다.

과거 오픈소스 프로젝트들이 MS 오피스 호환성(`.doc` 바이너리 포맷)을 맞추기 위해 리브레오피스(LibreOffice)에 들인 세월이나, 삼바(Samba) 팀이 윈도우 파일 공유 프로토콜을 역추적하는 데 쏟아부은 시간은 그 장벽의 높이를 보여 준다. 이제 AI 에이전트가 디컴파일러를 직접 구동하면서, 수년짜리 역공학의 비용이 몇 주, 며칠 단위로 내려앉고 있다.

## 상용 소프트웨어의 클린룸 모방

변화의 기폭제는 **GhidraMCP**, **REA(Reverse Engineer Anything)**, `ida-pro-mcp` 같은 프로토콜 브리지다. 과거에는 분석가가 어셈블리 조각을 복사해 챗봇에 붙여 넣는 수준이었지만, 지금은 AI 코딩 에이전트가 디컴파일러의 내부 API를 직접 쥔다. 에이전트는 블랙박스 바이너리의 실행 흐름과 교차 참조(Cross-Reference)를 스스로 추적하고, 메모리 구조와 UI 동작을 문서화한 뒤, 그 명세를 바탕으로 러스트(Rust)나 타입스크립트 같은 현대 언어로 코드를 새로 써 내려간다.

전통적 용어로 이를 **클린룸 재구현(Clean-Room Reimplementation)**이라 부른다. 원본 소스코드를 베끼지 않고 바이너리의 동작만 관찰·분석해 동일한 기능의 대체품을 만드는 방식이다. 두 팀의 엔지니어를 격리해 몇 년씩 걸리던 이 작업을 에이전트가 자동화하면서, 마이크로소프트 오피스(Word, Excel, PowerPoint)나 어도비(Adobe) 제품군을 모방한 오픈소스 클론—`ArtCraft`, `WordCraft`, `GridCraft`, `DeckCraft` 같은 프로젝트—이 단기간에 쏟아져 나오기 시작했다.

소프트웨어 벤더들은 이용약관(EULA)에 자동화 도구나 AI로 제품 기능을 관찰·복제(replicate)하는 행위를 금지하는 조항을 추가하고, 주요 상용 AI 모델 역시 바이너리 디컴파일 요청을 차단하는 안전 필터를 걸고 있다. 그러나 폐쇄형 바이너리 뒤에 숨겨 두던 기능적 독점의 비용 구조 자체가 이미 무너지고 있다.

## 게임 디컴파일과 정적 재컴파일의 가속

게임 분야에서도 같은 변화가 나타나고 있다.

과거 *슈퍼 마리오 64*나 *젤다의 전설: 시간의 오카리나* 같은 고전 게임의 바이너리를 1:1 C 소스로 복원(Matching Decompilation)하는 데는 전 세계 팬 커뮤니티가 달라붙어 수년이 걸렸다. 이제는 `GhidraMCP`와 에이전트 스웜이 이 공정을 자동화한다.

- **정적 재컴파일과 AI 리팩토링**: 구형 콘솔(N64, PowerPC 기반 Xbox 360 등)의 기계어를 통째로 C++로 번역하는 **정적 재컴파일(Static Recompilation)** 도구가 뽑아낸 스파게티 코드를 AI가 클래스와 타입으로 재구조화하고, 그래픽 파이프라인을 Vulkan이나 DirectX 12 같은 최신 API로 갈아끼운다.
- **병렬 에이전트 스웜**: 2000년대 윈도우 게임을 현대 OS로 이식할 때도 여러 에이전트 세션을 병렬로 띄워 오디오, UI, 물리 엔진, 맵 에디터 모듈을 분담해 역공학하고, 헤드리스 실행과 스크린샷 대조로 원본과 동일하게 돌아가는지 자동 검증한다.
- **'슬롭컴(Slopcomp)'의 범람**: 역공학 속도가 빨라지면서, 기존 1:1 장인 디컴파일 커뮤니티에서는 검증이 덜 된 AI 양산형 게임 포트·모작을 비꼬아 **'슬롭컴(Slopcomp)'**이라 부를 만큼 물량이 늘고 있다.

## 암호화만 빼고, 기능은 모두 모방된다

AI 리버스 엔지니어링에도 뚫지 못하는 영역은 존재한다. **RSA(비대칭키)나 SHA(일방향 해시) 같은 암호학 자체다.**

바이너리를 디컴파일해 검증 로직을 100% 읽어 내더라도, 개인키가 없거나 일방향 해시가 걸린 암호학적 장벽을 AI로 깨는 것은 불가능하다. 큰 수의 소인수분해나 해시 역산에는 신경망이 학습할 통계적 패턴이나 기울기(Gradient) 자체가 존재하지 않기 때문이다. 보안 연구에서 AI가 건드리는 지점은 수학 자체가 아니라 약한 난수 생성기나 잘못된 암호 모드 같은 **구현 결함** 탐색, 혹은 물리 장치의 전력·전자기파 누출을 분석하는 **부채널 공격**에 국한된다.

그러나 암호학적 장벽이 아닌 소프트웨어의 작동 원리—파일 파서, UI 상태 머신, 게임 물리 엔진, 상용 툴의 기능 로직—는 컴파일된 바이너리라도 AI 리버스 엔지니어링으로 **기능적 모방(Functional Mimicking)**이 가능하다. 코드 가상화나 패킹 같은 난독화 기법이 분석 시간을 지연시킬 수는 있지만, 로컬 CPU에서 실행되는 순간 명령어로 풀려야 하는 구조적 한계 안에서 완벽한 방패가 되지는 못한다.
